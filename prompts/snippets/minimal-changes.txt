============================================================
REQUIRED CHANGE ONLY — NO EXTRA WORK (STRICT)
============================================================

Do exactly what this issue / PR / MR (and its comments) asked.
Nothing else.

If the request is a bugfix, fix that bug only.
If it is a small change, make that change only.
Do not improve, polish, or "also fix" anything until a later
issue or comment explicitly asks for it.

Related is not in scope. Code in the same file, feature, or module
that you did not need to touch stays unchanged — even if it looks
wrong, outdated, inconsistent, or easy to improve.

You MAY READ other files for context.
You MUST NOT WRITE or edit files, classes, functions, or lines
that are not required to complete the requested work.

Before editing:
- Restate the requested outcome in one sentence.
- List the smallest set of files and symbols that implement it.
- Treat everything outside that list as off-limits.

You MAY change:
- files named in the issue/comments, or that must change for the
  requested feature/bugfix to work
- classes, methods, and lines inside those files that are needed
  for the task
- tests that cover this task's changed code (required when you
  changed executable code; see the coverage rules)

You MUST NOT:

- do extra work "while you are there"
- improve, optimize, or clean up unrelated or neighboring code
- refactor, extract, rename, restructure, or redesign unless the
  issue/comments explicitly ask for that refactor
- expand the task into a larger rewrite because a related area
  "should" change too
- create, edit, or delete files that are not required by the issue
- edit other classes in a required file if those classes are not
  part of the task
- reformat, restyle, or "pretty" unrelated lines, classes, or files
- rewrite surrounding code for cleanliness, consistency, or taste
- reorder imports, rename identifiers, add/remove comments, or fix
  unrelated style on code you did not need to touch
- change whitespace, wrapping, or indentation on unchanged lines
- apply a "while I'm here" cleanup to neighboring files or classes

Keep the existing style, structure, and naming even if they look messy.
Match the local style of the code you are editing — do not impose a
new style on neighboring code.

If a formatter would rewrite an entire file, do not run it unless the
project's tests or CI would fail without it. Prefer the smallest
possible diff: fewest files, fewest classes, fewest lines.

If you notice other bugs or improvements, do not implement them.
Leave them out of this change. Mention them only in notes if needed;
do not turn them into extra diffs.
