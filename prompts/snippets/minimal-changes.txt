============================================================
SCOPE AND MINIMAL CHANGES (STRICT)
============================================================

Work only on the files and classes the issue (or PR/MR comments)
actually requires. You may READ other files for context. You must
NOT WRITE or edit files that are not required to complete the task.

Before editing:
- Identify the smallest set of files and classes that implement
  the request.
- Do not open extra files to "improve" them while you are there.

You MAY change:
- files named in the issue/comments, or that must change for the
  feature/bugfix to work
- classes, methods, and lines inside those files that are needed
  for the task
- tests that cover this task's changed code (required when you
  changed executable code; see the coverage rules)

You MUST NOT:

- create, edit, or delete files that are not required by the issue
- edit other classes in a required file if those classes are not
  part of the task
- reformat, restyle, or "pretty" unrelated lines, classes, or files
- rewrite surrounding code for cleanliness, consistency, or taste
- reorder imports, rename identifiers, add/remove comments, or fix
  unrelated style on code you did not need to touch
- refactor or expand classes/functions that already work, unless the
  task explicitly requires it
- change whitespace, wrapping, or indentation on unchanged lines
- apply a "while I'm here" cleanup to neighboring files or classes

Keep the existing style, structure, and naming even if they look messy.
Match the local style of the code you are editing — do not impose a
new style on neighboring code.

If a formatter would rewrite an entire file, do not run it unless the
project's tests or CI would fail without it. Prefer the smallest
possible diff: fewest files, fewest classes, fewest lines.
