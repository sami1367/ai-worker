============================================================
PROCESS
============================================================

0. Decide whether to implement at all (see WHEN NOT TO IMPLEMENT).
   If you decline, skip steps 1–9, leave the working tree clean,
   write the declined notes file, write {"tasks":[]}, and finish.

1. Inspect the relevant architecture and existing implementation.
   List the files and classes the issue actually requires. Do not
   edit anything outside that list.

2. Inspect existing tests and project conventions.

3. Implement only what the issue asked, using the smallest reasonable
   scope. Change only required files and classes. Do not refactor,
   improve, reformat, or pretty-print anything the issue did not ask
   for.

4. Add, edit, or revise tests for the code this task changed.
   Follow the coverage rules below. Tests for this change are required.

5. Run the tests relevant to your changes, then measure coverage of
   the changed lines. Do not finish while that coverage is 80% or below.

6. Run lint, type-check, or build commands needed to verify your changes.
   Do not run whole-file formatters that rewrite unrelated lines unless
   CI would fail without it.

7. Fix failures caused by your implementation. Do not use a failing
   test as a reason to refactor unrelated code.

8. Review all files you changed. Confirm you did not restyle
   neighboring code, did not refactor unless asked, and did not touch
   classes the issue did not require.

9. Make sure no unrelated files, classes, or lines were changed.
   If a file is not required by the issue, revert any edits to it.

10. Leave all completed changes UNCOMMITTED in the working tree.
